Yes. I think Category Theory is unusually well matched to what you are already doing with sw-MLPL, but I would not initially make “support Category Theory” a language-design objective. I would use it as a forcing function and explanatory framework for functions, composition, data transformation, pipelines, effects, and abstractions that ought to stand on their own.

The distinction I would make is:

Category Theory should initially exercise sw-MLPL, not infect its syntax.

That gives you useful pressure on the language without turning sw-MLPL into a category-theory DSL.

Why sw-MLPL is a particularly interesting vehicle
A lot of introductory Category Theory material has an unfortunate gap:

diagram/equation → Haskell-ish notation → hand waving → next concept

sw-MLPL could instead provide:

concept → tiny executable example → inspect values → compose operations → visualize structure → verify laws

That fits your teaching-language direction very well.

And the APL/J influence makes this more interesting than simply recreating Haskell examples. Category Theory talks heavily about structure-preserving mappings and composition, while array programming is largely about structured transformations of structured data.

Those ideas intersect naturally.

For example, you already care about:

data -> transform -> transform -> result
Category theory gives a vocabulary for asking:

What kind of thing is this transformation?
Can these transformations compose?
What structure does the transformation preserve?
Does an identity transformation exist?
Do the expected laws hold?
Can we lift an operation into another context?
That could make Category Theory useful both for learning CT and for stress-testing MLPL's functional model.

Advanced curriculum evidence, 2026-08-12

The concrete success/failure context now provides the next supported bridge.
Mapping changes only a successful payload and preserves an existing failure;
executable fixtures verify identity and composition. Context-returning stages
also compose without a generic higher-kinded interface: left identity, right
identity, associativity, and failure short-circuiting all execute in sw-MLPL
0.20.0. The visual result is two complementary views: parallel success/failure
tracks for context map, and a fallible pipeline whose later stages visibly stop.

This evidence supports Lessons 12 and 13 now. It does not support claiming a
generic Functor or Monad abstraction. Lessons 14 and 15 should therefore reuse
the stable concrete context next, first combining independent computations and
then contrasting that with dependent bind. Recursion schemes, optics, and any
adjunction remain later capability-gated work.

Lessons 14 and 15 evidence, 2026-08-12

The same context cleanly exposes the programming distinction between
independence and dependency. A contextual function can be applied to an
independently obtained contextual scalar, and two successful feature values
can converge into a product record. Separately, bind can pass a loaded row
count into the batching decision that requires it. Identity/composition
fixtures, failure preservation, and deliberately broken outcomes all execute.

This is enough to teach applicative-style and monadic structure concretely,
but it does not create or require generic Applicative/Monad interfaces. The
current product helper deterministically retains the first failure rather than
accumulating diagnostics. The next research target is finite folds/unfolds;
recursive representation and bounded generation should be probed before those
lessons are designed.

Lessons 16 and 17 evidence, 2026-08-12

Finite arrays are the cleanest current representation. The useful fold law is
operational: doubling each metric before `reduce_add` equals doubling the
already folded summary, because scaling preserves addition. Squaring provides
the counterexample and prevents an invalid fusion. For generation, an explicit
seed, step, and count produce a deterministic arithmetic schedule. Recovering
seed and first difference regenerates lawful fixtures, while an irregular
sequence fails visibly.

This supports bounded fold/unfold teaching without recursive records. It does
not demonstrate general catamorphism, anamorphism, stream, or recursion-scheme
support, so no sw-MLPL feature request is justified by this step. Lawful nested
record access for Lesson 18 is the next supported research question.

Lesson 18 evidence, 2026-08-12

A practical nested model configuration supports a lawful learning-rate lens.
Named get, set, and update helpers execute get-put, put-get, and put-put while
preserving model name, batch size, and metadata. A deliberately broken setter
resets batch size and makes the get-put violation visible.

The implementation cost is manual immutable reconstruction: updating one
nested field repeats the surrounding record shape. For one concrete structure
this is understandable and self-documenting, not evidence for an optics DSL.
If a second materially different nested structure repeats the same boilerplate,
record-update syntax may become a generally useful sw-MLPL question. The next
step is to audit whether any constructions already implemented yield a genuine
and teachable adjunction; no lesson should be forced if they do not.

Lesson 19 decision, 2026-08-12

The audit found a genuine adjunction already latent in Lesson 5: diagonal
duplication is left adjoint to product. Its unit duplicates a value into two
views; its counit takes the matching left and right projections. Both triangle
composites return representative finite record values unchanged. Taking the
left projection twice breaks a triangle and returns `(3,3)` for `(3,5)`.

Fold/unfold, the success/failure context, and the model lens were rejected as
candidates because the implemented fixtures do not supply the categories,
hom-set correspondence, unit, and counit needed for those claims. The accepted
lesson is consequently narrow and honest: `diagonal ⊣ product` in the concrete
finite-set/record interpretation, with no proposed adjunction syntax.

Web custom-SVG presentation finding, 2026-08-12

Loading `web/array_functor.mlpl` exposed a presentation distinction: the web
renderer correctly recognizes an evaluation result beginning with `<svg` and
draws it, but the transcript first echoes the source expression after the
`mlpl>` prompt. When the expression itself is a full inline SVG literal, this
looks like a duplicate raw-SVG result. The prompt renderer also risks treating
an escaped hexadecimal color such as `#1a1b26` as an inline comment.

The local lesson now constructs the diagram with the readable, docstring-first
`array_functor_visual` function and assigns that constant result to the
`array_functor_visual` variable. MLPL assignment does not send the SVG payload
to the renderer, so one following bare-variable expression is required and is
the sole display. This binds the visual for later inspection and displays it
exactly once. It also uses `rgb(...)` colors, so the visual entry is readable
and avoids the comment ambiguity.
This is only a presentation workaround. sw-MLPL still needs either a dedicated
custom-SVG display primitive or a compact/collapsible source echo for visual
results. The remaining authored custom-SVG lessons should migrate to the named
visual-function pattern as their saga steps touch them.

Web SVG convention audit, 2026-08-12

The audit also found that most connectors were styled as lines without arrow

CT027-CT036 implementation evidence, 2026-08-12

CT025-CT026 and CT037-CT041 implementation evidence, 2026-08-12

The walking-arrow category uses `idA=0`, `f=1`, and `idB=2`. Postcomposition

CT042-CT044 implementation evidence, 2026-08-13

For the walking-arrow functor `F(A)=[10]`, `F(B)=[20]`, and `F(f)(10)=20`, the
element `10` generates the transformation components `eta_A(idA)=10` and
`eta_B(f)=20`. Evaluation at `idA` recovers `10`, and regeneration recovers
both components. Naturality is the executable equality `F(f)(10)=20`; changing
the B component to `21` supplies the failing witness.

The category of elements has nodes `(A,10)` and `(B,20)` with one induced
arrow over `f`. Reading the element values reconstructs `[10,20]`. This is a

or implementation of the general density colimit theorem.

CT054 implementation evidence, 2026-08-13
